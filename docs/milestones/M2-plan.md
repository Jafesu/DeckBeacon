## Clarifications to accepted ADRs (recorded, not new decisions)
- **ADR-0001 discovery wording:** the agent cannot raise an HA "Discovered" card, because `/pair` returns 404 outside an open window (ADR-0002, a security requirement). Discovery runs: agent browses `_home-assistant._tcp` (or takes `--url`), and the user starts the flow in HA. The "Discovered" UX is dropped in favour of the window gate.
- **ADR-0002 server key scope:** in Noise IK the responder must use its static key *before* it knows which device is connecting, so the integration uses **one static key per HA installation** (HA storage), not per config entry. Device keys remain per install, with per-entry revocation.
- **SAS confirmation surface in M2:** the agent CLI (`deckbeacon pair`). The Desktop Mode loopback page and Decky confirmation come in M4 (D2 allows CLI for v1).

## Acceptance criteria
- AC1 Noise: Go and Python produce byte-identical handshake and transport messages for every vector (XX and IK). Tampered ciphertext, a wrong static key, and a replayed handshake message are rejected in both languages.
- AC2 Pairing requires a confirmed SAS on **both** sides. `/pair` returns 404 with no open window. A window expires after 10 minutes and accepts exactly one device.
- AC3 No HA access token is ever present on the agent (CI grep check over agent sources and state files written in E2E).
- AC4 Telemetry from the recorded trees maps to HA entities with correct units and device classes. Values become `unavailable` when the device is disconnected or the value is `null`, and `last_seen` persists.
- AC5 Two agents pair to one HA as two devices with stable unique IDs. A restart of HA or the agent needs no re-pairing.
- AC6 Events are deduplicated across reconnects (resume from `last_received_event_seq`). Backfilled events are flagged `live: false`.
- AC7 Commands: replayed `command_id` → `duplicate`. Expired TTL → `expired`. Unknown or unsupported command → `rejected/unsupported`.
- AC8 Deleting the device in HA revokes it: the agent reports `revoked` and stops retrying aggressively.
- AC9 Pre-auth limits: oversize frame, handshake timeout, and garbage handshake are closed without crashing. Failures are recorded.
- AC10 Diagnostics contain no keys or secrets (canary test).
- AC11 CI green: Go, Python protocol, integration tests (HA 2026.5 minimum + latest), E2E, govulncheck, secret scan.

## Hardware caveat
No SteamOS device is available (D7). Collectors are validated against **recorded or synthetic sysfs trees** modelled on Steam Deck LCD/OLED and a Dell G15. They are clearly labelled synthetic until replaced by real captures from HV-T1…T7.

### Findings during M2
- HA progress-step tasks must be **background tasks**: tracked tasks block `async_block_till_done` for the whole 10-minute window.
- Removing a config entry unloads it first, so the device sees a 1012 close and then `permission_denied` on reconnect. The agent handles both. Documented in the test.
- A static `/proc/stat` correctly yields `cpu.usage = null` forever (no delta). Real hardware is needed to show non-null CPU.
- Go encodes `71.0` as JSON `71`. HA state strings may differ from the float's text form; entity tests compare accordingly.

### Known limitations (carried forward)
- **No real SteamOS hardware** (D7): collector paths and values are validated only against synthetic trees. Capability-matrix telemetry rows stay `research` until HV-T1…T7 run on the Dell G15 / Steam Deck.
- mDNS discovery is verified with a local fake responder only, not on a real LAN.
- Remote failover (local→remote→local) logic is implemented and unit-tested in Go against a single fake. A real two-path test belongs to M5.
- SAS confirmation on the device is CLI-only in M2 (decision D2). Decky and Desktop Mode surfaces come in M4.
- Systemd unit is untested on SteamOS (lingering and hardening options need HV-S1/S2).
