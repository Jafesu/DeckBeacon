# G15 M8 artwork survey (read-only), 2026-11-17

- **Host:** the owner's Dell G15, SteamOS. Collected by the on-device Claude session at the cloud session's request (M8, ADR-0009).
- **Read-only:** no sudo, installs or changes. No credential files were opened. shortcuts.vdf was read for appid and AppName only (covered by the earlier approval). The grid `.json` files were not opened.
- **Redactions:** userdata ID, home paths.
- **Note:** this is the summary relayed from the on-device session. The full per-file table for six appids stays in `docs/research/evidence/G15-m8-artwork-2026-11-17.md` on the G15 (uncommitted).

**1. Steam's artwork cache (librarycache)**
- 3,039 top-level entries (3,038 appid folders plus `assetcache.vdf`), 10,329 files, 1.3 GB.
- Each file can sit either directly in `<appid>/` or one level down in `<appid>/<sha1>/`, so the agent must check both. `library_capsule.jpg` and `markers.svg` only ever appear in the `<sha1>/` folders.
- Extra file names beyond the six listed:
  - `<appid>/<sha1>.jpg` is the game icon, almost always 32x32.
  - `library_hero_blur.jpg` is 192x62.
  - `markers.svg` (7 files).
  - There are no `_2x` or `.png` versions of the capsule, header or hero.
- The real dimensions don't always match the names (read from the image headers, because `file` reports density for JPEGs):
  - `library_600x900.jpg` is 600x900 for 1,037 files but **300x450 for 949**.
  - `library_capsule.jpg` is 300x450.
  - `header.jpg` and `library_header.jpg` are 460x215.
  - Hero images are mostly 1920x620, but 169 are 1920x1080 and 65 are 1280x720.
  - `logo.png` is 640 wide with heights from 127 to 360.
- The evidence file has a table of every file for the six requested appids. Notably, 271590 has no top-level `header.jpg` (only `<sha1>/library_header.jpg`), and 1091500 keeps everything except its icon under `<sha1>/`.

**2. Coverage for installed apps (40 appmanifests, one library folder)**
- Portrait 32, header 40, hero 33, logo 30. Every installed app has at least a header.
- Missing a logo only: 6000, 6020, 32430 (the three Star Wars games).
- Missing a portrait: 228980 (redistributables).
- Missing portrait, hero and logo: the four Steam Linux Runtimes and three Proton versions. Every app without a portrait is a tool or runtime.

**3. Symlinks and permissions:** no symlinks. Every file is owned by `deck` with mode 755, so the agent can read them.

**4. Non-Steam shortcut art:** the grid folder exists (one user ID, redacted) but only covers 2 of the 8 shortcuts:
- **Discord (2961728726):** portrait 600x900, wide 920x430, hero 1920x620, logo 876x170, `_icon.ico` and a `.json`.
- **Google Chrome (3922850944):** the same set. Its portrait **`3922850944p.png` is actually a JPEG**, so the agent should detect format from the file's leading bytes, not the extension.
- The `.json` files are 92 bytes each. I didn't open them.
- **Hollow Acre (4244106195) has no grid art**, and neither do the other five shortcuts.
- I got the shortcut IDs from `shortcuts.vdf`, reading only the appid and name fields, which is what your earlier approval covers.

**5. Steam's cache and shortcuts:** the cache has nothing for any of the 8 shortcut IDs.

**6. File sizes (10,328 images in the cache)**
- Largest 16.2 MB (a `logo.png`), median 46.6 KB. **406 files are over 512 KB**: 205 portraits, 190 heroes, 5 logos, 3 `markers.svg`, 2 icons, 1 header.
- Hero images run up to 3.65 MB (median 283 KB) and portraits up to 632 KB (median 215 KB).
- The agent will need a size cap or downscaling before sending artwork.

## Consequences for the agent (applied in `internal/artwork`)
- Input cap raised from 8 MiB to 32 MiB (largest real logo is 16.2 MB). The pixel-count check before decoding stays the real guard.
- Every candidate in `<appid>/` and `<appid>/<sha1>/` is measured, and the largest image wins (949 files named `library_600x900.jpg` are 300×450).
- The format is sniffed from the bytes, never the extension (Chrome's `…p.png` is a JPEG).
- Shortcut grid names confirmed: `<u32>p`, `<u32>`, `<u32>_hero`, `<u32>_logo`. Shortcuts without grid art get a placeholder in the cards.
- Downscaling and re-encoding are required: 406 cache images exceed 512 KB.
