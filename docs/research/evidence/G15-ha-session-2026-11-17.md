# G15 ↔ Home Assistant: first real pairing and session (2026-11-17)

- **Device:** Dell G15 5520, SteamOS 3.9.5, Desktop Mode. Agent built on the device from `c29c3b6`.
- **Home Assistant:** the owner's production instance, core 2026.11.1 (HAOS, aarch64). DeckBeacon integration copied from the same branch by the owner.
- **Run by:** the owner (pairing needs a human to compare codes). HA state read by the cloud session through the read-only HA connector.

## Steps and results
| Step | Result |
|---|---|
| `deckbeacon pair --url http://<ha-lan>` + HA "Add integration → DeckBeacon" | Same 6-digit code on both sides. Confirmed on both. `Paired with "Home"`. |
| Hint printed after pairing | **Bug:** it said `systemctl --user enable --now deckbeacon.service`, but the unit does not exist before `deckbeacon service install`. Fixed in `c29c3b6`. |
| `deckbeacon service install` (no `--at-boot`) | Wrote `~/.config/systemd/user/deckbeacon.service`, enabled and started it. `active (running)`, 12.3 MB RSS. |
| Agent log | `new boot detected` → `connected transport=local integration=0.1.0` within 0.1 s of start. |
| `deckbeacon status` | Paired with Home, not revoked, URL kinds `[manual cloud]`. HA has no internal URL configured, so the pairing URL is the local path and HA Cloud is the remote fallback. |
