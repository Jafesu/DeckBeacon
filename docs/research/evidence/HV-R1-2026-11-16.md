## Findings
1. **Gate resolved:** a custom integration's WebSocket endpoint is reachable and bidirectional through HA Cloud remote UI, with device-key auth and no HA token on the client. This matches the source review (snitun binds a `SockSite` to HA's aiohttp runner).
2. **Measurement bugs found and fixed** (and fed back into the protocol):
   - Command-ack dedupe state persists across connections, so a second connection receives two `duplicate` frames. The original soak loop assumed one reply per ping. The client now matches the pong by echo token.
   - The echo token was an int64 nanosecond count sent as a JSON number, which Go decodes as float64 and loses precision. **Protocol v1 now caps integers at 2^53−1** (`COMPATIBILITY.md`).
3. **Reconnect is mandatory:** any intermediary (relay, proxy, HA Cloud server migration) can drop long-lived connections. ADR-0001's reconnect and resume (`resume_after_event_seq`) is required, not optional. M2 must include an automatic reconnect test with a forced drop.

## Not tested (by choice)
- Toggling remote UI off and on: would interrupt the owner's remote access. Defer to a scheduled maintenance window or a test HA instance.
- Multi-hour soak and Nabu Casa server migration: needs a long-running real device (M5).
