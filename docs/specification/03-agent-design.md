# Agent design and service lifecycle
Go agent installed in user-owned persistent path (proposed ~/.local/share/deckbeacon) with state/config under XDG conventions and systemd --user unit. User-session startup is default; test behavior in Gaming and Desktop modes, login/logout, suspend/resume and SteamOS upgrades. Do not assume user service survives logout or boots before login.

Optional boot-time monitoring requires explicit opt-in, platform validation, least-privileged dedicated system helper/service and documented installation/rollback. Split responsibilities: boot helper performs only basic OS metrics/network presence; session agent performs Steam, Decky, desktop notifications and user-scoped actions. Coordinate using authenticated local IPC with permissions. One shared stable device identity, single HA device and event stream. Avoid duplicate collectors and transport connections; use leader/ownership rules and deterministic handoff. If boot helper unsupported, report capability unavailable.

State machine: installing -> unpaired -> pairing -> connected_local / connected_remote -> reconnecting -> suspended/offline -> recovering; service health independent of connection health. On suspend flush bounded queue; on resume detect clock/network changes and reconnect. Shutdown commands must acknowledge before loss of connection. Systemd restart policy with backoff, no restart storm. Persist commands and events atomically; do not replay non-idempotent commands. Diagnostics must redact secrets.

Suggested collectors: system, steam, downloads, game library, sessions, network, updates. Capability-based provider interfaces; graceful degradation and mockable tests. Agent offers local pairing UI without Decky; bind loopback only, protect against CSRF/origin abuse; prefer Unix sockets for Decky IPC.
