# Security and pairing
Unique per-install keypair and stable device ID. Pairing initiated from HA, Decky or agent local setup, with short-lived code/challenge and explicit on-device approval. Exchange and verify peer identities; trust stored securely. Authentication for all commands; TLS for network transport, optional signed envelopes where necessary. Anti-replay via command IDs, expiry and durable deduplication. Rotate/revoke keys and recover pairing with explicit user consent.

Separate monitoring, standard controls, game management, notifications, administrative power and update privileges. Separate local/remote permission policies; network proximity alone grants no trust. Enforce on agent, not just HA UI. Minimize privileged helper; no open unauthenticated local endpoints. For sensitive commands, game-aware safe windows, confirmation, audit trail. Secrets never in logs, diagnostic bundles, metadata or frontend. Protect backups of device identity with strong encryption; reject simultaneous identity clones. Threat model malicious LAN peer, compromised Decky plugin, stolen agent credential, replayed remote commands, spoofed HA discovery, compromised release artifact and HA account compromise.
