# Networking and remote access
Local-first mDNS/Zeroconf plus manual address. Agent initiates outbound remote sessions; no required inbound Deck ports. HA discovers remote URL (including HA Cloud where enabled) during pairing; agent securely caches local and remote profile. Automatic fallback local -> remote when LAN fails, remote -> local after stability threshold. Preserve identity and deduplicate sessions/events across transitions. External HTTPS/WSS manual URL supported.

BLOCKING FEASIBILITY GATE: HA Cloud remote URL discovery does not prove support for arbitrary custom endpoints or authenticated bidirectional agent traffic. Prototype HA-supported WebSocket authentication/command path, Cloud compatibility and restricted device credentials. If unsupported, evaluate secure authenticated HTTPS polling or validated external URL/VPN; Cloudhooks alone are not a general bidirectional transport. No unrestricted HA long-lived access token on devices. Never claim Cloud remote support without end-to-end testing. Document limits, proxy behavior, revocation and security review. Suggested heartbeat 15s and timeout 45s are provisional, tune with tests.
