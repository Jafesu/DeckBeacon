# Testing and acceptance
Unit tests for Go collectors, state machine, command policy, replay/dedupe, update rollback; Python HA config flows/entities/reauth/actions; TypeScript Decky/dashboard components; protocol cross-language contract fixtures. Integration tests for pairing, multi-device, network failover, sleep/resume, stale telemetry, event replay, offline notifications, permission denial, SteamOS update, removable libraries, download lifecycle. Hardware test matrix: Steam Deck LCD/OLED where accessible and supported non-Deck SteamOS hardware. Test Gaming and Desktop Mode, boot helper on/off, Decky installed/uninstalled, local and remote connections.

No milestone complete without reproducible evidence, documented source/OS version and known limitations. High-risk actions require explicit real-device validation. Cloud transport feasibility is a blocking gate before remote claims. Release must preserve identity across updates, reject unsigned artifacts, enforce least privilege and provide recovery after failed update.
